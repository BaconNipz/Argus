# Argus v0.9.0 — reminder alerts and spoken replies

Reminder delivery has been confirmed by the user on their phone. The remaining report was that notifications appeared in the status bar and shade without a banner or sound. This update addresses the app settings behind alerts and adds a way to check the phone settings that can silence them. It also adds native offline spoken replies while speech-input testing continues.

## Reminder changes

The original reminder category used standard importance, which does not request a heads-up banner. New categories now request high importance, the phone's notification sound and vibration. The old alert-only-once option has also been removed: a daily or weekly occurrence can alert even if the previous notification was not dismissed.

Android preserves notification category settings after creation. Raising the app's default cannot raise an existing category, so Argus keeps that category and gives you a direct settings shortcut. It does not delete the category, bypass Do Not Disturb or change phone volume. See [Android notification channel behaviour](https://developer.android.com/develop/ui/compose/notifications/channels).

### What to do on your phone

1. Open **Routines → Reminder sound and banner settings**.
2. Choose **Alert**, select a **Sound**, and enable **Show as pop-up** if that switch is available. Names can vary between Samsung software versions.
3. Return to Argus and read **Sound and banner status**. It checks the reminder category, phone sound mode, notification volume and Do Not Disturb.
4. Tap **Send test alert now**. This posts one notification using the same settings as reminders, without saving or changing a routine.

Argus can report configuration and that a notification was posted; it cannot prove a banner appeared or a sound was heard. Samsung pop-up preferences, the current screen/lock state and phone sound settings still control presentation. The scheduling mechanism is unchanged, so reminders remain approximate and can be delayed by battery management.

## Offline spoken replies

1. Open **Command → Spoken replies**.
2. Choose an **Installed offline voice** and tap **Test voice**.
3. Run a typed or reviewed spoken command. If it takes you to another screen, return to Command and tap **Speak Reply offline**.
4. Use **Stop speaking** to end playback. Starting microphone capture or leaving Command also stops it.

Argus lists only voices the current Android text-to-speech engine reports as usable without network synthesis and without missing voice data. It checks the selected voice again before speaking. If your chosen voice disappears, select another; it does not silently substitute a network voice. These checks follow [Android's voice metadata](https://developer.android.com/reference/android/speech/tts/Voice#isNetworkConnectionRequired()) and [voice-installation flags](https://developer.android.com/reference/android/speech/tts/TextToSpeech.Engine#KEY_FEATURE_NOT_INSTALLED).

If no suitable voice is listed, open **Android text-to-speech settings** to choose an engine or install voice data, then return and tap **Refresh voices**. Installation can need internet access. Playback uses media volume. Replies remain readable on screen when speech is unavailable, including in the browser. The earlier browser speech-output shortcut has been replaced by this checked native path.

Speech output is manual. It does not automatically read notifications or personal records, and it does not turn Argus into a conversational AI model. The existing command vocabulary and speech-input review process are unchanged. The output adapter saves the voice preference, but not reply text or audio.

## Verification and limits

JavaScript checks cover alert advice, output completion/cancellation, stale callbacks and unavailable-native behaviour. Native tests cover offline-voice selection as well as existing reminder timing and microphone-session rules. CI compiles the Android app; the APK's manifest and bundled assets are verified before delivery.

Actual banner/sound behaviour, recognition quality and offline playback still require the phone test. A voice engine's installed/offline metadata is its report, not a network capture. No visual or physical-device test is claimed by the development environment.

Version **0.9.0**, Android version code **10**. Database schema remains **4**. The development APK includes v0.7 and v0.8 and remains debug-signed, so it may not install over a build signed with a different debug key. Permanent release signing still awaits the four private repository secrets.

## Next development task

Use device feedback to fix remaining alert or speech issues, then add useful reminder notification actions such as Snooze and Done. These should update the existing schedule consistently and remain local to the phone.
