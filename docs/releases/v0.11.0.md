# Argus v0.11.0 — Phone backups and broader commands

This update makes it easier to carry Argus data between installations and gives typed/spoken commands more room for natural wording. It uses local rules and the existing on-device speech adapter; no AI account or paid API is required.

## Save and review a backup

1. Open **Settings → Save backup to phone**.
2. Choose a local folder, such as a folder inside Downloads, and tap **Save**.
3. Wait for **Backup saved and checked**. Argus writes the file, reopens it and checks that the bytes match. Cancelling the picker does not count as a saved backup.
4. Choose that file under **Choose a backup to review**, then tap **Review backup**. This checks the file and its attachments and shows the contents without replacing anything.
5. When you actually want to restore, use **Replace data with this backup** and confirm the replacement.

Backups contain memories, cases and sources, evidence attachments, voice-note audio, reminders, tools, settings and action/event history. They are unencrypted JSON files, capped at **64 MiB including encoded attachments**. Save them somewhere private. Android document files remain outside Argus's private app storage; see [Android's document storage guidance](https://developer.android.com/training/data-storage/shared/documents-files).

Restore checks all records and decodes attachments before cancelling schedules. All local stores are then replaced in one transaction. Restored reminders are paused, and pending actions require approval again. Previously completed actions keep their history. If storage fails during replacement, the old records remain, but Android reminders may already have been cancelled; review Routines before enabling them again. A file picker or save interrupted by Android activity/process destruction may need to be repeated. Discard a file if Argus reports that it could not save and verify it.

In a normal browser, Save backup requests a download; the browser cannot confirm disk persistence, so use Review backup on the downloaded file. Older Android shells need the v0.11 native build for the new export path. This update does not retroactively fix export in an older installed APK, and it does not resolve mismatched debug signing keys. Do not treat an unverified backup as a reason to remove an existing installation.

## More ways to ask

These examples work with typing or with **Start listening → Use text in command box → Run Command**. The interpretation appears below the command before you run it.

| Say or type | What Argus prepares or does |
| --- | --- |
| Could you remember that the spare key is in the shed? | Saves a local memory note after Run Command |
| Please make a note that the case needs another source | Saves a memory note |
| Start an investigation into @example_user | Creates a local case |
| Save this link https://example.com | Saves the link in the inbox case |
| Find my notes about example.com | Searches local records |
| What do you remember about Casey? | Searches local records for Casey |
| Show me my reminders | Opens Routines |
| Take me to my cases | Opens Investigations |
| What is due today? | Lists up to five enabled reminders scheduled for today |
| Give me a summary | Counts local memories, cases, evidence and enabled reminders |
| Back up my data / Restore a backup | Opens Settings; you choose the file operation |
| Say that again / Read that back | Reads the previous reply with the selected offline voice |
| Stop speaking | Stops spoken output when run; the Stop button is also available |
| What can you do? | Displays command help |

Prefixing an instruction with “please”, “could you”, “I'd like you to”, “Argus” or “Hey Argus” is supported. Similar phrasings work within these command families. Unfamiliar language, conditions and recognised chains of actions need editing. This is still an English phrase parser, not unrestricted conversation or a local LLM. It does not listen for a spoken Stop while text-to-speech is playing; tap Stop, or end playback before starting another speech capture.

## Reminder times in commands

- “Remind me in twenty minutes to take a break.”
- “Set a reminder to drink water in 2 hours.”
- “Set a reminder for tomorrow at nine thirty am to call mum.”
- “Remind me to review notes every day at nine am.”
- “Remind me every Monday at 14:30 to review the case.”

Supported durations include minutes, hours, calendar days and weeks, plus “in half an hour”. Explicit clocks accept AM/PM, noon, midnight or 24-hour `HH:MM` time. Dates and weekly/daily repeats follow the phone's calendar. Bare times such as “tomorrow at seven”, mixed durations such as “two hours and five minutes”, past times and unsupported patterns leave the time empty for you to set. Nonexistent daylight-saving times also need correction.

Nothing is scheduled from the parser alone. Review the task, local date/time and repeat in Routines, then save and enable it. Reminder delivery remains approximate under Android background scheduling.

## Why this build does not continuously listen for “Hey Argus”

A dedicated offline wake phrase is feasible as a separate feature, but it needs its own wake detector, microphone lifecycle, accidental-trigger testing and phone battery measurements. Repeatedly restarting the current speech recognizer is unsuitable: Android says the general [SpeechRecognizer API is not intended for continuous recognition](https://developer.android.com/reference/android/speech/SpeechRecognizer). Argus uses the dedicated on-device variant for short captures.

Android also provides a user-selected [VoiceInteractionService](https://developer.android.com/reference/android/service/voice/VoiceInteractionService) that can remain active for voice interaction. Integration and available hotword support would need testing on the actual Samsung device; this does not guarantee access to Bixby's low-power wake behavior.

For this build, tap **Start listening** first. “Hey Argus” is an optional part of the sentence afterward; it cannot wake Argus while closed or on the lock screen. The next practical voice step is a shortcut to Command, followed by a separately opt-in wake-detector prototype if battery and recognition tests justify it.

## Build and checks

Version **0.11.0**, Android version code **12**, database schema **4**. Automated coverage includes phrase variants, time interpretation and ambiguity, daylight-saving gaps, backup validation/attachment decoding, restored action permissions, native staging limits/order/cancellation and Unicode chunk transfer. CI compiles and tests the native code before building the APK. Physical-phone file-picker/restore and recognition checks still need user testing. Release signing continues to depend on the existing private repository secrets.
