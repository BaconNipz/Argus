# Argus v0.7.0 — reminders and routines

This update gives Argus a useful first background task: reminding you about something after you close the app. You can create a one-off reminder or repeat it daily or weekly. Everything needed for this runs on the phone; no account, cloud AI or subscription is involved.

## What changed

The new **Routines** screen has a title, date/time, repeat setting and optional note. Saving creates a paused reminder. **Enable reminder** sends it to Android's scheduler. **Pause** stops future notifications, **Edit** lets you change the details, and **Delete** removes it and cancels pending work. Saving edits pauses the old schedule until you enable the revised one.

Commands such as `remind me to export an Argus backup` open this form with the title filled in. Argus asks you to choose the time; it does not guess a date from free text. Existing reminder action drafts can also open this editor from Bridge.

The screen shows whether notifications are enabled and includes buttons for requesting permission or opening Android's notification settings. Each reminder shows its schedule, time zone and the last notification posted. That status means Android accepted the notification; it does not mean you have read or completed the task.

Daily and weekly repeats use the calendar in the time zone where you saved the reminder. They keep the chosen time through daylight-saving changes. If a phone has been off for several days, Argus posts one overdue notification and moves to the next future repeat, avoiding a pile of catch-up notifications. If you travel, edit and save to adopt the phone's new time zone.

## How to use it

1. Open **Routines** in the v0.7 Android APK.
2. Tap **Enable notifications** and allow Android's notification request. If you previously denied it or disabled the notification channel, open **Android notification settings**.
3. Enter a title and a future local date/time. Choose Once, Daily or Weekly.
4. Tap **Save reminder**, review its card, then tap **Enable reminder**.
5. Close Argus normally. When Android posts the notification, tapping it opens Routines.

The browser version can save and edit reminders, but cannot run these Android notifications. A reminder whose time has already passed must be edited to a future time before you enable it again.

## Backups and existing data

The local database upgrades from schema 3 to 4 by adding a reminders store. Existing memory, cases, sources, evidence and other records remain in their existing stores. Backups include reminder definitions. Import replaces local data after confirmation, cancels existing native schedules, and restores reminders paused. Wiping Argus also cancels its native reminder work.

Native schedule preferences are excluded from Android's automatic backup and phone-to-phone transfer. When an old web mirror has no matching Android schedule, Argus shows it as paused. Import does not authorise background tasks on another device.

## Timing and battery behaviour

These are approximate reminders, not exact alarms. Android can defer background work for battery saving or system load. Force-stopping Argus can prevent delivery until it is reopened. A powered-off phone cannot post notifications. Use the phone's alarm app when the exact minute matters. This follows [Android's WorkManager scheduling model](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work).

Android 13 and later require notification permission; users can also disable the app or reminder channel separately. Argus checks both before scheduling and before posting. If permission is off when due, it pauses the reminder and records why. See [Android notification permissions](https://developer.android.com/develop/ui/views/notifications/notification-permission).

## Verification

- Local tests cover time/title validation, paused restoration, native state reconciliation, reminder command routing and approval checks.
- Native unit tests cover one-off completion, daily/weekly repeats, missed occurrences and Adelaide daylight-saving transitions.
- GitHub Actions runs the local and native tests before building the APK. Development branches build a debug artifact without publishing a release or loading release signing keys.
- Physical S23 Ultra notification delivery, force-stop/reboot behaviour and Samsung battery restrictions still need device validation; desktop and unit checks cannot prove these.

## What comes next

The next development slice is native offline speech input: detect what the phone supports, add push-to-talk, and feed recognised text into the existing command screen for review. Notification triage and multi-step routines remain separate future work.

The permanent APK update chain still needs private release-signing secrets. This update does not configure or replace the signing key.
