# Argus v0.10.0 — Snooze and Done

The user reported that v0.9 was working on the phone. This update adds two ways to handle reminders directly from a notification: **Snooze 10 min** and **Done**. The same controls are available in Routines for an active reminder alert.

## How to use it

1. Save and enable a reminder for a future time.
2. When it arrives, expand its notification to reveal the buttons.
3. Tap **Snooze 10 min** to clear the card and request another alert about ten minutes after the action is handled.
4. Tap **Done** when you have handled that occurrence. A one-off is marked complete; a daily or weekly routine remains enabled for its next regular time.

Use **Pause** in Routines when you want to stop the routine, including a pending snooze. Swiping away a notification or tapping its body does not mark it Done. Tapping the body opens Routines, where its current alert can still be handled. Existing notifications posted by older builds do not gain the new buttons; use a newly triggered reminder.

The **Send test alert now** button remains a sound/banner check and does not create a reminder, so its test notification does not offer Snooze or Done.

## What happens to repeated reminders

Snoozing changes only the current occurrence. For example, snoozing today's 9 am daily reminder does not change tomorrow's 9 am reminder. Routines shows the snooze return time separately from the next regular time.

If the next regular occurrence becomes due before an old snooze returns, the new occurrence takes priority. This also applies after a long battery-saving delay: Argus does not pile an older snooze on top of a newer regular reminder. Snoozes remain approximate WorkManager reminders, so Android can deliver later than the requested ten minutes. Notification action handling can also take a moment; refresh Routines if you return before the background action finishes.

## Preventing mistaken actions

Each new alert is associated with the version of the reminder that produced it. Editing, pausing or deleting the reminder invalidates the old alert. Once Snooze or Done is accepted, another tap on that same alert cannot repeat the action. The buttons use explicit immutable Android PendingIntents and a private receiver, following [Android notification action guidance](https://developer.android.com/develop/ui/compose/notifications/create-notification#Actions).

Pausing and deletion cancel both regular and snooze work. Backup restore still creates paused reminders and removes active alert/snooze tokens. The local view clears stale action controls when the native record no longer provides them. The background receiver hands work off promptly, following [Android broadcast guidance](https://developer.android.com/develop/background-work/background-tasks/broadcasts).

## Status and verification

Routines distinguishes a one-off notification that has been posted (`notified`) from one marked Done (`completed`). It also shows a pending snooze and the most recent Snooze/Done handling time. Older completed reminders keep their existing historical status.

Automated tests cover one-off completion, continuing repeats, snooze timing, regular-occurrence precedence, duplicate/stale actions, paused restoration and native/local status merging. CI compiles the receiver, workers and APK. APK contents and version metadata are verified before delivery. The new notification buttons still need a phone test; no physical-device test is claimed by the development environment.

Version **0.10.0**, Android version code **11**. Database schema remains **4**. This build includes v0.9's alert settings and offline speech input/output. Development APKs remain debug-signed and may not install over builds signed with a different key. Permanent release signing still awaits private repository secrets.
