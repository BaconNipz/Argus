# Argus v0.14.0 — Background Hey Argus

The v0.13 phone test confirmed that the wake phrase works but often misses the user's voice. That does not establish that the case is responsible: the small model also missed synthetic voices before phone testing. v0.14 adds microphone-volume feedback and the requested background workflow. It uses the same English wake model; improved recognition accuracy is not claimed.

## One-time phone setup

1. Open **Command**. Confirm **Start listening** works with your installed offline language, and allow the microphone if needed.
2. In **Hey Argus in other apps**, allow notifications. The ongoing notification provides a Pause control.
3. Tap **Set Argus as digital assistant**, then select Argus in Android's prompt. This changes the phone's current default digital assistant. If the prompt is unavailable, use Android Settings → Apps → Default apps → Digital assistant app. Samsung's wording can vary.
4. Leave **More sensitive** selected for the first comparison. **Run supported local commands after wake** is initially selected; clear it if you want recognised text to wait for review.
5. Tap **Enable Hey Argus by default**. Wait until its status says it is listening, then switch to another app.
6. Say **Hey Argus**, pause, and wait for the vibration before speaking the command. Argus requests Command through Android's assistant session. The vibration comes from the command recognizer's ready callback, not the earlier wake detection.

If Argus is not selected as the digital assistant, wake listening can still run, but the detection waits for you to tap its notification. A tap must be fresh: an unclaimed wake ticket expires after twenty seconds. Merely opening a shortcut or supplying text in an Android intent cannot run a command.

## Default-on behaviour

After the initial enable step, the choice is remembered. Listening continues while other apps are open and resumes after a command/cooldown. The app can start the enabled service when opened; Android's selected voice-interaction service can also request startup when the system makes it ready. This is not a guarantee of restart after every reboot, force-stop, battery restriction or Samsung process-management decision. Reopen Command and use **Apply settings / Retry** if the notification is missing.

**Pause Hey Argus**, either in Command or its ongoing notification, remembers the off choice. It stays off until explicitly enabled again. There is no boot receiver, forced restart loop, overlay permission or accessibility automation.

This build listens only with the screen on and phone unlocked. Screen-off/lock pauses microphone capture; unlock allows it to resume. It does not unlock the phone or execute locked-screen commands. The foreground five-minute test remains available after pausing background listening.

## Commands after wake

With automatic local routing enabled:

| Example | Result |
| --- | --- |
| “Remember to bring my keys” | Saves a local memory. |
| “Search copper” | Opens local search results. |
| “Start case weekend project” | Creates a local case. |
| “Open memory” | Navigates within Argus. |
| “Give me a summary” | Summarises local records. |
| “Remind me in twenty minutes to stretch” | Opens a reminder draft for review, saving and enabling. |
| “Open https://example.com” | Queues an external action for approval. |
| An unrecognised command | Keeps the transcript for review. |

Supported commands go through the existing deterministic local parser. A wake event itself cannot dispatch or approve a phone action. Available offline spoken replies can read the result. Typed drafts and unfinished recognised text are protected; use or clear them before another automatic capture. Ordinary tap-to-speak retains its review step.

## Hearing and battery checks

The level meter displays RMS volume in dBFS and flags samples near clipping. It is not a recognition score. Speak at the same distance with and without the case; compare the volume reading and detection. Normal volume with missed phrases suggests a recognition/model limitation. Quiet readings alone do not prove a blocked microphone: room noise, speaking distance and Android audio processing also affect them.

More sensitive uses the existing v0.13 score 4.0 / threshold 0.10. Standard remains 2.0 / 0.25. More sensitive can trigger accidentally, including during conversation. No gain boost or new accuracy claim is introduced. Wake samples remain in short memory buffers; only level measurements reach the web UI. No recorded wake audio is saved or uploaded.

Longer listening uses battery. This is CPU-based keyword detection, not a claim of Bixby-style hardware hotword efficiency. Check warmth/battery use during a short unlocked-phone session before relying on it for a full day. The model closes while paused or during a command; microphone ownership is shared across all Argus speech paths so two internal recorders cannot overlap.

## Implementation and validation

The native microphone foreground service has an ongoing low-importance notification and is not exported. Assistant and recognition services require Android's system binding permissions. The assistant session runs separately and requests no foreground-app screenshots or assist data. Its activity launch uses Android's `startAssistantActivity` API. The recognition adapter uses only the dedicated on-device recognizer.

Wake tickets are generated inside Argus, have a twenty-second claim window, can be claimed once only while visible/unlocked, and expire after at most sixty seconds of command handling. Pause and cancellation revoke the ticket. The audio gate is released only after the owning recorder/recognizer/output closes. Native enable preferences are excluded from Android backup and device transfer; local restore/wipe also pauses background voice.

Node tests cover capture gates, stale/malformed tickets, local versus draft routing, unknown commands and volume feedback. Native tests cover audio ownership, duplicate/stale claims, lock/foreground gating, timeouts and Pause. CI compiles the real Android services and runs the full native suite. Unit tests do not establish that Samsung granted the role, launched the assistant activity, or recognised real speech successfully.

Phone validation still needed: assistant selection, automatic opening over another app, first-word capture, supported command execution, reminder/external-action review, Pause from the notification, screen lock/unlock, app switching, competing recorder recovery, restart behaviour, recognition and battery use.
