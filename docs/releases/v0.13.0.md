# Argus v0.13.0 — Foreground Hey Argus test

This development build adds an experimental offline wake phrase to Command. You explicitly start one listening window, say “Hey Argus”, pause, then speak after command capture is ready. The wake detector and its English model run on the phone and ship inside the APK. No account, API key or separate wake-model download is required.

## Try it on the phone

1. Open **Command**. In **Speak a command**, allow microphone access and confirm that ordinary **Start listening** works with the selected offline language. Command transcription still needs Android's available on-device speech service/language pack.
2. Clear or use any recognised text left from the previous capture.
3. In **Hey Argus**, keep **Standard** selected and tap **Listen for Hey Argus · 5 min**. Wait for the message saying it is listening for the phrase.
4. Say **Hey Argus**, then pause. After the short vibration, wait for **Listening** in the speech panel before saying something such as “Could you remind me in twenty minutes to take a break”. The phrase and command are separate turns in this prototype; speaking them together can lose the start of the command.
5. Review the recognised words, choose **Use this text**, and then **Run Command**. Reminder commands open a draft for review, saving and enabling. External actions still need approval.
6. Start another wake test explicitly when ready. It does not rearm itself after a command.

If Standard misses your voice, try **More sensitive**. It may also trigger on unrelated speech. A detection starts a bounded command recording, so use **Cancel** if it activates accidentally. No command is executed by the detection itself.

## When listening stops

Wake mode stops after one detection, five minutes, **Stop wake listening**, leaving Command, switching apps, locking the phone or destroying the activity. It does not listen on the home screen or behind other apps. It keeps the microphone and screen active during the test; this is an intentional, bounded test mode rather than an all-day assistant.

Wake audio is processed in short memory buffers and is not saved, uploaded or attached to records. The existing recognizer supplies command text for review. Native code prevents wake capture and command capture from owning the microphone together. Spoken replies are stopped before either recorder starts. There are no new permissions, background microphone services, boot starts or persisted wake-enable settings.

## Model and build

- Runtime: sherpa-onnx 1.13.8 Android AAR with ONNX Runtime statically linked.
- Model: English GigaSpeech Zipformer KWS 3.3M, 2024-01-01. Upstream int8 encoder/joiner and floating-point decoder; 16 kHz mono input.
- Custom phrase: `▁HE Y ▁A R G US @hey_argus`, encoded using the model's SentencePiece vocabulary.
- Standard: keyword score 2.0, threshold 0.25. More sensitive: score 4.0, threshold 0.10. Both use four active paths and two trailing blank frames.
- Packaging: ARM64 (`arm64-v8a`), matching the S23 Ultra. This APK is larger because it contains the runtime and model. It does not target x86 emulators or 32-bit phones.
- `python3 scripts/prepare-wake-runtime.py` fetches pinned artifacts, checks exact lengths and SHA-256, and copies only named regular files. Python 3.11+ and curl are build dependencies. Cached downloads can be supplied with `--cache-dir PATH`.
- Model/runtime binaries are build outputs excluded from Git. Model provenance, asset digests and upstream licence notices are included in the APK.

Primary documentation: [sherpa-onnx keyword spotting](https://k2-fsa.github.io/sherpa/onnx/kws/index.html), [runtime release](https://github.com/k2-fsa/sherpa-onnx/releases/tag/v1.13.8), [model release](https://github.com/k2-fsa/sherpa-onnx/releases/tag/kws-models).

## Checks and limits

Node tests cover visible/ready/idle capture gates, stale sessions, Stop overriding queued detections, duplicate handoffs, malformed events and the narrow bridge contract. Native policy tests cover release-before-claim, stop during model loading, cancellation after detection, one-use tokens, foreground checks and exact timeout boundaries. CI compiles the real Android integration and runs native unit tests before producing an APK. None of these unit tests is a physical microphone or UI test.

An offline FFmpeg/flite synthetic check loaded the selected model and tried three “Hey Argus” voices plus four unrelated clips. At the selected Standard settings it detected one of the three synthetic positives; More sensitive detected two. Neither setting triggered on the four unrelated clips. This tiny artificial set is not a recognition-accuracy estimate, noise test or battery measurement. It establishes that this model/configuration can detect the phrase, while also showing why device tuning is needed.

Phone validation still needed:

- Repeat the phrase naturally at normal phone distance; compare both sensitivity settings in quiet and ordinary room noise.
- Confirm that the vibration/handoff leads to usable command text, including the first word, and that review is still required.
- Try Stop during startup/listening, leave Command, switch apps and lock the phone. Confirm Android's microphone indicator clears and no late command capture starts.
- Let a test reach five minutes. Confirm it ends, the screen can sleep again and another test requires a tap.
- Test another recording app, microphone privacy controls, and repeated arm/cancel cycles for unavailable-microphone feedback and recovery.
- Check accidental triggers during ordinary conversation and observe phone warmth/battery use. Longer sessions or background activation wait for this evidence.

Version: **0.13.0**, Android **versionCode 14**, backup schema **4**. The development branch builds a debug APK and does not publish a main release. Private release signing remains a separate setup step; retain a verified backup before any reinstall needed because of a signing-key mismatch.
